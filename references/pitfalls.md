# Common Pitfalls

1. **`enableTelemetry` is not wired.** `Schema.ts` and `Configuration.ts` accept `enableTelemetry` (default `true`), but `initializeOidcClient` in `src/lib/client.ts` does not pass it to `ServerClient`. Don't assume setting it changes behavior, and don't claim in docs that the SDK sends or suppresses telemetry based on it without checking `@auth0/auth0-server-js`.
2. **Examples are outside CI.** `examples/` is skipped by ESLint and not covered by `tsconfig.json`, `npm run build` or `npm test`. The demo app (`examples/demo`) has its own `package.json`, uses pnpm, and pins its own `vitest` major (^2), so a public-API change can break it without any CI failure. Run `cd examples/demo && pnpm test` and `pnpm run build` when you change exported behavior.
3. **Mocked tests can hide state-store bugs.** Unit and flow tests mock `@auth0/auth0-server-js`. Session mutations must preserve the `internal` field (`createdAt`, `sid`) that `StatelessStateStore` needs to compute cookie `maxAge`; `updateSession` reads raw `StateData` for that reason. Cover such changes in `test/integration/`.
4. **`next()` in standalone route handlers.** Calling `next()` from `callback`/`logout` dispatches to Hono's 404 when the handler is mounted as a standalone route (a past bug, see the comments in `src/middleware/callback.ts` and `logout.ts`). Return the redirect instead of continuing the chain.
5. **Two version files.** `.version` (read by `release.yml`, includes a `v` prefix) and `package.json` `version` are bumped together by the release flow and may differ on `main` between releases. Don't "fix" the mismatch in a feature PR.
6. **Path alias needs `tsc-alias`.** `@/` imports only work after `npm run build` runs `tsc-alias`; compiling with bare `tsc` leaves `@/` paths in `dist/`.
7. **Multiple secrets.** `session.secret` may be an array for key rotation; only the first element is the active encryption key (`resolveSecret` in `src/lib/client.ts`). Keep that order when touching secret handling.
